# FACE CURLING — 비주얼 준비안 (v0.1)

- 상태: **제안**. POC A 손맛 검증이 끝난 뒤 착수한다 (명세 1.3: 물리·조작 재미 먼저, 명세 12장: POC A 통과 전 화려한 UI 투자 금지).
- 예외: 소리와 기본 파티클은 손맛 평가 자체에 영향을 주므로 POC A 튜닝 중에 먼저 넣을 수 있다 (6장 1단계).

## 1. 아트 디렉션

### 1.1 후보 세 가지

| | A. 스티커 + 장난감 링크 **(추천)** | B. TV 스포츠 중계 | C. 종이 공작 |
|---|---|---|---|
| 한 줄 | 실제 사진에서 오려 낸 얼굴 스티커를 장난감 같은 아이스링크에서 붙이는 게임 | 진지한 올림픽 중계 화면에서 친구 얼굴 부위가 굴러감 | 레인·캐릭터·스톤 전부 종이 오리기 |
| 웃음 포인트 | 귀여운 세계 × 실사 얼굴 조각의 대비 | 진지함 × 황당함의 대비 | 손으로 만든 엉성함 |
| 제작 비용 | 중 (로우폴리 + 단색 위주) | 상 (사실적 재질·조명·중계 그래픽) | 중하 (평면 위주, 대신 3D 깊이감 약함) |
| 모바일 성능 | 좋음 | 나쁨 | 좋음 |
| 얼굴 추출 품질 문제 | **흰 스티커 테두리가 마스크 경계의 허점을 가려 줌** | 그대로 드러남 | 일부 가려짐 |

### 1.2 추천: A. 스티커 + 장난감 링크

추천 이유:

1. **게임의 본질이 '오려 붙이기'다.** 얼굴 부위를 사진에서 잘라 다른 자리에 붙이는 행위가 곧 스티커다. 세계관을 따로 설명할 필요가 없다.
2. **POC B의 품질 리스크를 숨긴다.** 명세 R11·R12대로 자동 추출과 빈 얼굴 복원은 완벽하지 않다. 부위 PNG에 흰 다이컷 테두리(3~6px)와 얇은 그림자를 두르면 거친 마스크 경계가 '일부러 그런 스타일'이 된다. 결과 화면에서 원본 위치에 붙여도 경계가 덜 어색하다.
3. **세로 모바일에서 읽기 쉽다.** 단순한 형태와 색은 작은 화면에서도 스톤·빗자루·판정 원을 구분하기 좋다 (명세 1.3-5: 가독성 우선).
4. **에셋을 구하기 쉽다.** CC0 로우폴리 캐릭터·소품(Kenney, Quaternius 등)으로 시작해 나중에 자체 제작으로 바꿀 수 있다.

### 1.3 톤 기준

- **팔레트**: 얼음은 차가운 흰색·연하늘, 링크 벽과 소품은 채도 있는 원색 2~3개(빨강 계열 1, 파랑 계열 1, 노랑 포인트). 얼굴 사진이 가장 따뜻한 색이 되도록 주변을 차갑게 둔다.
- **형태**: 둥근 모서리, 굵은 비례(큰 머리·짧은 몸), 과장된 두께.
- **재질**: 대부분 단색 + 약한 그라데이션. 반사·굴절은 얼음 한 곳에만 쓴다.
- **글꼴**: 제목·스탬프는 굵고 둥근 한글 디스플레이체(예: Jua, Black Han Sans 계열), 본문은 Pretendard 또는 Noto Sans KR. GitHub Pages에서 자가 호스팅하고 사용 글자만 서브셋.

## 2. 맵 (링크·보드)

| 요소 | 현재 | 목표 |
|---|---|---|
| 얼음 | 단색 평면 | 미세한 긁힘·페블 노멀 텍스처, 약한 반사(환경맵 1장), 스톤이 지나간 자국이 서서히 사라짐 |
| 얼굴 보드 | 얼음 위 평면 | **얼음 아래에 깔린 대형 포스터**처럼 보이게: 얼음 층의 약한 흐림·하이라이트를 위에 얹음. 정답 위치는 점선 '여기 붙이세요' 다이컷 표시 |
| 라인 | 빨강·파랑 띠 | 실제 컬링 라인(티·호그·백 라인) 문법을 빌려 발사선·스위핑 구간·보드 경계를 표시 |
| 벽 | 회색 박스 | 둥근 패딩 보드 + 가짜 스폰서 배너(게임 내 농담 문구, 실존 브랜드 금지) |
| 배경 | 어두운 단색 | 관중석 실루엣 판넬(평면 카드 몇 장), 천장 조명 빛줄기. 멀리 있는 것은 전부 평면 |
| 조명 | 반구광 + 방향광 | 위에서 내려오는 경기장 조명 1개 + 은은한 환경광. 그림자는 스톤·캐릭터만, 모바일은 블롭(원형) 그림자 |

추가 맵 테마(후속): 겨울 연못(눈 쌓인 야외), 동네 목욕탕 타일 위 얼음판 같은 농담성 테마. **물리 수치는 테마와 무관하게 동일**하게 둔다 (게임별 랭킹 공정성, 명세 5.4).

## 3. 캐릭터

### 3.1 기본

- 로우폴리 장난감 체형: 큰 머리, 짧은 팔다리, 두꺼운 패딩 조끼, 털모자.
- **얼굴 자리에 플레이어가 고른 얼굴 스티커를 붙일 수 있다** (선택). 제작한 친구 얼굴을 캐릭터에도 붙이면 결과 화면과 이어지는 개그가 된다.
- 색 커스터마이즈: 모자·조끼 2색. 랭킹·물리에 영향 없음.

### 3.2 애니메이션 목록 (glTF 애니메이션 클립)

| 클립 | 쓰는 때 | 비고 |
|---|---|---|
| idle | 투구 준비, 정지 대기 | 숨쉬기 정도 |
| run | 목표점으로 이동 | 이동 속도로 재생 속도 조절 |
| sweep_push / sweep_pull | 스트로크 | **스트로크 애니메이션 길이 = `strokeDurationMs`**. 판정은 지금처럼 게임 로직이 하고, 애니메이션은 그 타이밍을 따라간다 |
| sweep_run | 달리면서 스위핑 | 상체 sweep + 하체 run 블렌드 |
| stumble | 번드 | 넘어질 듯 휘청 |
| cheer / despair | 결과 점수 구간별 | |

### 3.3 판정과 외형 분리 (이미 구조가 있음)

- 몸 판정 원(`bodyJudgeRadius`)과 빗자루 판정 원은 **외형 크기와 무관**하게 유지한다. 외형을 바꾸면서 판정이 바뀌지 않게, 판정 원은 바닥에 얇게 표시하는 옵션을 남긴다 (연습 모드 기본 켬, 기록 모드는 약하게).
- 빗자루 머리 모델의 중심 = 게임의 `broom` 좌표. 모델 원점을 거기에 맞춘다.

## 4. 스톤과 스티커

- 스톤 본체: 납작한 장난감 퍽(실제 컬링 스톤의 손잡이 형태는 유지해 회전이 보이게).
- 윗면: **실제 부위 사진을 오려 낸 원형 스티커** (POC B 이후). POC A 동안은 지금 아이콘 유지.
- 스티커는 정방향 고정, 손잡이만 회전 (명세 3.10·R07).
- 퍽 주변 색 고리는 가시성용으로 유지하되 부위 색과 맞춘다 (명세 5.3 제안).

## 5. 이펙트

원칙: **모든 이펙트는 게임 상태를 알려 주는 피드백**이어야 하고, 스톤·빗자루·판정 원을 가리면 안 된다 (명세 R20).

| 상황 | 시각 | 소리 | 우선순위 |
|---|---|---|---|
| 스위핑 스트로크 | 빗자루 끝 얼음 가루, 강도에 비례한 양 | 빗질 소리, 강도에 따라 음높이·볼륨 | **1** |
| 스위핑 유효 영역 | 스톤 앞 얼음이 살짝 반짝이며 녹는 띠 | — | **1** |
| 스톤 이동 | 얼음 위 자국(리본 데칼, 서서히 사라짐) | 굴러가는 저음 루프, 속도에 비례 | **1** |
| 쿠션 진입 / 빗자루 스침 | 스톤 테두리 노랑 → 빨강 펄스 | 짧은 경고음 | **1** |
| 충돌 | 충격 링 + 얼음 조각, 만화 효과 글자 스티커("딱!") | 돌 부딪히는 '딱' | 2 |
| 발사 | 짧은 카메라 당김, 바람 줄 | 미끄러지는 출발음 | 2 |
| 번드 | 화면 테두리 빨강 플래시, BURNED 도장이 쾅 찍힘, 캐릭터 휘청 | 호루라기 | 2 |
| 이탈 | 스톤이 벽에 튕겨 나가며 별 | 관중 '아~' | 3 |
| 결과 | 퍽에서 스티커가 떼어져 날아가 얼굴에 철썩 붙음(부위별 순차), 점수 집계, 고득점 시 색종이 | 스티커 붙는 소리, 관중 반응 | 2 |

주의:

- **히트스톱(충돌 순간 멈칫) 금지**: 물리 시간을 멈추면 결정론·재현성이 깨진다. 카메라 펀치와 효과만 쓴다.
- 카메라 흔들림은 명세 4장대로 투구·충돌 순간에만 약하게.
- 진동(햅틱)은 Android만 가능. iOS에서는 소리·시각으로만 전달.

## 6. 기술 준비 (코드 구조)

### 6.1 게임 이벤트 스트림 — 가장 먼저

지금 `Game.emit()`은 HUD 로그용 문자열이다. 이것을 **타입이 있는 이벤트**로 바꿔, 이펙트·소리·결과 연출이 게임 로직을 건드리지 않고 구독하게 한다.

```text
launch {partId, speed, spin}
stroke {kind, valid, intensity, tick}
cushionEnter / contact {stoneId, ticks}
collision {a, b, impulse, x, y}
stoneStop {id, x, y}
out {id}
burn {cause, stoneId}
turnEnd / result {...}
```

- 이벤트는 틱 안에서 쌓이고, 렌더 프레임에서 소비한다. 결정론 로직(Game·Simulation)은 그대로.
- 충돌 세기는 Rapier 접촉 힘 이벤트 또는 충돌 전후 속도 차로 계산.

### 6.2 렌더러 분리

현재 `renderer.js` 하나를 다음으로 나눈다.

```text
render/
  stage/rink.js, board.js, background.js   맵
  actors/stone.js, character.js            모델 + 애니메이션
  fx/particles.js, trails.js, stamps.js    이펙트 (이벤트 구독)
  camera.js                                지금의 카메라 리그
  quality.js                               품질 단계
  assets.js                                로더 + 로딩 화면
audio/
  mixer.js                                 Web Audio, 루프 + 원샷, 첫 터치 후 시작
```

### 6.3 에셋 파이프라인

- Blender → glTF(.glb), meshopt 압축. 텍스처 KTX2(Basis). 1단위 = 1m, Y-up, 모델 원점 규칙(스톤 = 바닥 중심, 빗자루 = 접촉점).
- 소리: 짧은 원샷은 m4a/ogg, 루프는 이음새 없이 편집. CC0 출처를 `assets/CREDITS.md`에 기록.

### 6.4 모바일 성능 예산 (세로, 중급 Android 기준 60fps 목표)

| 항목 | 예산 |
|---|---|
| 드로콜 | 100 이하 |
| 삼각형 | 15만 이하 |
| 그림자 | 방향광 1개, 그림자맵 1024 이하. 저사양은 블롭 그림자 |
| 후처리 | 저사양 끔. 고사양만 약한 블룸·비네트 |
| 첫 로딩 | 5 MB 이하 목표: Rapier wasm 분리(현재 JS에 base64로 1.3 MB 포함), 모델 0.5 MB, 텍스처 1 MB, 소리 1 MB, 글꼴 서브셋 |

- 품질 단계 low/medium/high를 첫 몇 초의 프레임 시간으로 자동 선택하고, 설정에서 바꿀 수 있게.
- 프레임이 떨어지면 픽셀 비율을 먼저 낮춘다 (물리는 고정 틱이라 영향 없음).

## 8. 결정이 필요한 것

1. 아트 디렉션 A/B/C 중 선택 (추천 A).
2. 캐릭터 얼굴 스티커 기능 포함 여부.
3. 에셋 조달: CC0로 시작 후 교체 / 처음부터 자체 제작 / 외주.
4. 소리를 POC A 단계에서 먼저 넣을지 (추천: 넣음).
