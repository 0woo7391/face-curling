# FACE CURLING — POC A (물리·스위핑 손맛)

명세 `v1.2` 12장 **POC A**를 구현한 프로토타입입니다. 사진 처리 없이 **가상 평균 얼굴 앵커 6개**를 깐 보드에서
투구·회전·스위핑·번드·충돌을 검증하고, 수치를 실시간으로 튜닝하는 것이 목적입니다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # 헤드리스 테스트 (Node, Rapier 포함)
npm run build    # dist/ — GitHub Pages 하위 경로에서도 동작 (base: './')
```

바로 시험해 볼 수 있는 배포본: https://claude.ai/artifact/DoCeSh1AbLfVT5Q2oBYeBV (비공개, 소유자만 열람)

화면은 **세로 하나**입니다. 폰은 전체 화면, PC는 같은 세로 화면을 가운데에 띄웁니다. 조작만 마우스/터치로 다르며,
입력 종류는 기기가 아니라 실제 입력(`pointerType`)으로 판단합니다.

## 조작

| 단계 | 조작 |
|---|---|
| 시작 | 홈에서 시작(기록) 또는 연습. 📷 얼굴 카드로 사진 얼굴 만들기 |
| 부위 선택 | 아래 3×2 버튼 |
| 회전 | 던지기 전에 ⟲ ⟳ 칩 (누를 때마다 ● → ●● → 끔) |
| 던지기 | **새총**: 누른 채 아래로 당겼다 놓기. 당긴 반대 방향(±12°), 당긴 길이 = 파워. 위로 올리면 취소 |
| 스위핑 (기본: 자동 따라가기) | 캐릭터가 알아서 스톤 앞에 붙음. **누른 채 좌우로 흔들기** (폰: 화면 아무 데나 손가락 하나로 좌우 문지르기, PC: 왼쪽 버튼 누른 채 1~2 cm 좌우로) — 빗자루가 손 위치를 그대로 따라감 |
| 스위핑 (직접 이동, 일시정지 메뉴에서 전환) | 마우스 잠금 + 이동 = 목표점, 좌클릭 밀기 → 우클릭 당기기 / 폰: 왼쪽 조이스틱 + 오른쪽 문지르기 |
| 보기 | `T` 레인 탑다운 전환, 왼쪽 아래 보드 미니맵 |

**모바일 (세로 기본)**: 투구 단계는 손가락 하나로 같은 드래그. 스위핑은 두 엄지로 —
왼쪽 절반을 누르면 그 자리에 조이스틱이 생기고(기울이는 동안만 목표점 이동, 놓으면 그 자리에 고정),
오른쪽 절반을 **위로 쓸면 밀기, 아래로 쓸면 당기기**입니다. 방향이 바뀔 때마다 스트로크 1회.

- 스톤 앞 **초록 영역**에서 끝난 스트로크만 효과가 있습니다.
- 빗자루가 **노란 원**(쿠션) 안 → 경고 + 자동 회피 보조. **빨간 원**에 `graceTicks` 이상 겹치면 BURNED. 몸이 움직이는 스톤에 닿으면 즉시 BURNED.
- 기록 모드: 번드 = 투구 무효 + 다른 스톤 원위치 + 해당 부위 0점. 연습 모드: 원위치 후 재투구, `직전 투구 되돌리기` 가능.
- Pointer Lock이 안 되면(미지원·3회 실패·디버그에서 강제) 레인 탑다운 고정 + 절대 좌표로 바뀝니다 (명세 3.8.1 대체 모드).

## 사진으로 얼굴 만들기 (POC B-1)

상단 📷 → ① 사진 고르기(촬영 대상 동의 확인) → ② 자르기(끌기·확대) → ③ 다듬기 → ④ 빈 얼굴 → 플레이.

- **자동 추출**: MediaPipe Face Landmarker(브라우저 안에서 실행, 사진은 밖으로 나가지 않음)로 눈썹·눈·코·입 6개 부위의 초기 마스크를 만든다. 귀는 제외([확정] v1.1).
- **다듬기**: 부위를 고르고 칠하기/지우기 붓으로 손가락·마우스 보정, 되돌리기, 자동으로 되돌리기.
- **빈 얼굴**: 마스크 합을 조금 넓혀 지우고 주변 색을 끌어와 채운 뒤(다중 해상도 푸시-풀) 약한 잡음을 더한다. 블러 기반 1차 버전이라 코·입처럼 넓은 곳은 평평한 얼룩이 생긴다(명세 3.4 주의 사항). '다시 붙이기'로 원본과 비교.
- **게임 연결**: 빈 얼굴이 보드에 깔리고, 퍽 윗면에 부위 스티커, 결과 화면에서는 퍽 대신 실제 크기 스티커(흰 테두리)가 최종 위치에 붙는다. 채점 기준점 = 마스크 무게중심, 정규화 = 얼굴 윤곽 상자 대각선.
- **퍽 크기 자동 맞춤**: 정답끼리 너무 가까우면(실제 얼굴은 눈썹-눈 간격이 좁음) 퍽 반지름을 줄여 동시 배치를 보장한다(명세 5.3-3).
- 만든 얼굴은 이 브라우저의 IndexedDB에 저장되어 다시 열면 이어서 쓴다. '기본 얼굴로'로 되돌린다.
- MediaPipe 로더는 번들에 포함하고(`tools/vendor-mediapipe.mjs`, `npm install` 때 자동), wasm·모델은 `public/mediapipe/`에서 같은 출처로 받는다. 외부 CDN을 쓰지 않는다.
- `ARTIFACT=1 npm run build`: 한 파일 배포용(지연 로딩 조각 포함, 모델은 base64 텍스트로 받음).

## 피드백 설계

글자 대신 크기·두께·색·소리로 **내 입력에 대한 반응**을 보여줍니다. 어디에 두라는 정답 안내(예상 경로 점선,
멈출 곳 표시, 빗자루 위치 가이드, 정답 위치)는 보여주지 않습니다 — 불확실성이 재미의 일부입니다.

| 상황 | 반응 |
|---|---|
| 방향 | 노란 화살표 |
| 회전 | 스톤에 붙은 고리(길이·두께 = 세기, 색 = 방향, 화살촉) + 스톤 손잡이가 그 속도로 제자리에서 돎 |
| 파워 | 스톤 옆에 서 있는 막대가 차오름(초록→노랑→빨강), 스톤이 뒤로 당겨짐, 화살표가 길어짐 |
| 방향 | 회전 고리 바깥에서 시작하는 화살표. 지금 단계 표시만 진하고 끝난 단계는 흐림 |
| 스위핑 | 빗자루 머리 **초록 = 효과 있음**, 노랑 = 너무 가까움, 빨강 = 닿음. 스톤 둘레 고리가 찰수록 세게 쓰는 중. 얼음 가루·빗질 소리가 강도에 비례 |
| 다음 입력 | PC: 화면 아래 마우스 버튼 그림 중 눌러야 할 쪽이 밝아짐. 폰: 문지르기 판의 ▲/▼가 밝아짐. 순서가 틀리면 흔들림 + 낮은 소리 |
| 위험 | 빗자루가 가까우면 스톤 둘레 노란 고리, 닿으면 빨강. 몸이 가까우면 발밑 빨간 고리 |
| 충돌 | 퍼지는 고리, 얼음 조각, '딱' 소리, 짧은 카메라 흔들림 |
| 번드 | 화면 테두리 빨강 + BURNED 도장 + 호루라기 + 캐릭터 휘청 |

소리는 Web Audio로 합성합니다(파일 없음). 상단 🔊로 끄고 켭니다. Android에서는 진동도 납니다.
게임은 발사·스트로크·충돌·번드 등을 이벤트로 내보내고(`game.drainEvents()`), 이펙트·소리는 그것만 구독합니다.
이벤트를 읽든 안 읽든 게임 결과는 같습니다(테스트로 확인).

## 디버그 · 튜닝 패널 (상단 ⚙)

모든 물리·스위핑·쿠션 수치를 실시간으로 바꿀 수 있고, 변경값은 브라우저 `localStorage`에 저장됩니다.
`변경값_복사`로 기본값과 다른 값만 JSON으로 복사해 공유할 수 있습니다. 통계 폴더에 충돌 수, 원인별 번드 수,
직전 투구 정지 위치·평균 스위핑 강도, 정답 간섭·직선 경로 막힘이 표시됩니다.
콘솔에서는 `window.__game`으로 게임 상태를 볼 수 있습니다.

## 검증한 것 / 아직 안 한 것

자동 테스트(`npm test`, 50개)로 확인한 것:
- 감속 역전 없음, 곡률이 속력을 바꾸지 않음, 시계/반시계 곡률 부호, 스위핑 시 더 멀리·덜 휨
- 최소 파워는 보드에 못 미치고 최대 파워는 보드를 넘음
- 같은 입력 → 같은 결과(재현성), 60Hz/144Hz/불규칙 프레임에서 같은 틱 수
- 스위핑 봇으로 정지 거리 증가(번드 없음), 유효 영역 밖 연타는 효과 0
- 충돌 시 기존 스톤 이동, 전체 정지 전 다음 투구 잠김
- 기록/연습 모드 번드 처리, 빗자루 유예·리셋, 쿠션 경고, 자동 회피 상한
- 기본 레이아웃 정답 간섭 없음, 6투구 후 결과
- 스트로크 입력 버퍼(끝나기 100 ms 전 다음 입력 1개 예약), 터치 문지르기 판정, 조이스틱 월드 고정·비선형 반응

헤드리스 Chromium(iPhone 13 에뮬레이션, 실제 멀티터치 이벤트)으로 확인한 것: 세로 레이아웃, 조이스틱+문지르기로
정지 거리 +2.6 m(번드 0, 스트로크 전부 유효). 데스크톱: 투구 UI 흐름, Pointer Lock 획득, 실제 DOM 마우스 이벤트 경로로 스위핑 시
정지 거리 +1.24 m(번드 0), 번드 연출, 결과 화면, 콘솔 오류 없음.

**사람 손으로 조작해 보는 테스트는 아직 안 했습니다.** POC A의 핵심 질문(조작이 재미있는가, 번드가 너무 잦은가,
마우스 이동량이 견딜 만한가)은 실제 마우스로 플레이해 봐야 답할 수 있습니다.

## POC A에서 사람이 측정할 것 (명세 11.2)

1. **마우스 이동량**: 레인 끝까지 따라가는 데 마우스를 몇 번 들어 옮겨야 하는지. 시작값은 가로 0.02 m/px, 진행 방향 ×1.5.
2. **번드 빈도**: 숙련자 기준 게임당 평균 1회를 넘으면 쿠션 수치를 먼저 조정 (명세 3.9).
3. **스위핑 체감**: 강도 게이지와 실제 거리 변화가 연결되어 느껴지는지, 스트로크 110 ms가 적당한지.
4. **퍽 반지름별 충돌 빈도**와 정답 간 동시 배치 가능 여부.
5. **곡률·감속 계수**: 회전 100%로 얼마나 휘는 게 재미있는지.
6. Chrome·Edge·Firefox에서 좌/우 클릭 조합, 우클릭 메뉴, Pointer Lock 진입·해제(`Esc`).
